## DRY was a null experiment

Qwen full-v0 and full-v0-dry generated byte-identical content for all calls
on visits 02, 09 and 14, with identical token totals and extraction/review
outcomes. HTTP metadata and timings differ. DRY retained a 64-token history
and sequence breakers including quotation marks, colon and newline. It cannot
compare whole long objects across these boundaries. Increasing its history
would also penalize the verbatim evidence quotes the evidence lane requires.
The recorded profile remains available, unchanged; no DRY tuning is proposed.

## Quarantine and review

Only normal completions with valid, duplicate-free, finite JSON and exactly
`{"assertions": [...]}` can yield valid siblings. Each item is independently
validated using the same strict JSON-mode schema parser and version. Invalid
items are stored in private extraction.json with call/window, zero-based
position, raw item, error type and location. Error messages do not enter logs.
The extraction pipeline always requests quarantine diagnostics; strict helper
callers used by existing frozen replays retain all-or-nothing parsing.

A quarantined item is never merged, mapped, rendered as clinical text, or
counted as a prediction/fact. Its visit review item is
`malformed_item_quarantined`, material, failing, reduced-schema FAIL, and
blocks final export under A4. Valid siblings retain their own lane results.
Preview and note rendering work; the note visibly states
“N extracted item(s) were malformed and withheld — review required”. No raw
malformed text is copied into the note or validation review summaries.

Review accepts only dismissal with a nonblank reason, reviewer and role. It
writes a private append-only receipt with time, target digest (including the
visit transcript hash) and dismissal
diff; the caller retains the receipt with the run. Changed item bytes invalidate
the receipt. Dismissal never promotes an item into a fact, approves it, or
waives a failed lane. After dismissal the note still reports items withheld,
with reviewed/dismissed status. The export decision and collection builder
both enforce quarantine blockers when supplied the run's visit review items.
This extends the existing Python review/export integration; no review UI is
introduced by Step 10.

Non-JSON, wrong top level, duplicate keys anywhere, non-finite numbers
(including overflowing exponents), reasoning, truncation and loop stops still
yield no partial assertions. Reaching `MAX_ASSERTIONS` counts every element,
including malformed ones, and fails the response. Schema v1's exported JSON
Schema remains byte-identical; a nonblank quote pattern needs a later version.
Eval stores quarantine counts per encounter and per model run and excludes
quarantines from predictions and matching.

## Streaming, loop guard and repetition-v2

Every extraction request now uses `stream=true` and
`stream_options={"include_usage": true}`. SSE content strings are concatenated
exactly, without stripping whitespace. A string/escape-aware incremental scanner
recognizes only complete direct objects in the root assertions array. Identity:
kind, casefolded whitespace-collapsed concept_text, polarity, and sorted exact
(segment_id, quote) evidence pairs. The fourth identical identity closes the
HTTP response and raises `LoopDetectedError`. Three occurrences are allowed.
The private partial body is a discarded attempt, mode 0600 in a 0700 run
folder. It contributes no assertions. The pipeline uses truncation's same
adaptive split, overlap, reuse and minimum-window rules, with reason
`extractor repetition loop`; an unsplittable segment fails the visit.
`[extractor.loop_guard]` pins `loop-guard-v1` and limit 4 for every profile,
recorded in extraction/evaluation metadata. This is a development-derived guard,
not evidence of clinical accuracy or a method for fixing repeated assertions.

The transport reconstructs choices[0].message.content, finish_reason, usage
and timings into the prior response shape. It waits past the finish-reason
chunk for the empty-choices usage/timings event and `[DONE]`. Each call records
`transport=sse`. Claude's live pinned-build probe found byte-identical greedy
reassembly with json_schema and generation cancellation within about 0.3 s
of closing the connection. This step rechecks the saved exchange's framing
and tests synthetic exchanges offline; it makes no new live cancellation claim.

The saved sample has 120 JSON SSE events: 117 content-bearing events, an initial
role event with null content, a finish event, and a final usage/timings event.
Its usage reports 120 completion tokens. Thus stopped calls count received
content chunks, labelled `received_content_chunks`; these exclude server-only
or unreturned tokens and are not interchangeable with final server usage.
The one-token-per-content-chunk assumption comes from the pinned-build probe;
the saved sample alone cannot prove token boundaries or account for the
three-token discrepancy. Completed calls retain server usage and method
`server_usage`. Aggregate measurements retain method counts and all attempts.

Step 9's timeout is now an absolute total wall deadline across the stream:
`ceil(1.5 * (output_tokens / generation_rate + input_tokens / prompt_rate) + 30)`.
The first-event deadline is `ceil(1.5 * input_tokens / prompt_rate + 30)`;
subsequent events have a 60 s idle deadline. Socket read allowances shrink
to the earlier deadline, and the reader checks deadlines between reads,
including trickled partial events. Failures record first_chunk, idle or total
as distinct timeout phases. Timeouts do not trigger inference retries.

Repetition-v2 retains all v1 fields and adds complete_assertions_seen,
max_identical_assertion_repeats, duplicate_assertions (occurrences beyond the
first), and polarity_flip_pairs (distinct unordered polarity variants sharing
kind, normalized concept and evidence). Complete objects count even if later
schema-invalid; incomplete tails do not. Diagnostics scan returned and discarded
text and never authorize acceptance. Synthetic tests reproduce long-object loops,
compact output, polarity flips and escaped delimiters.

Request snapshots deliberately change **only** stream and stream_options.
Tests pin the new request hashes and reconstruct the historical nonstreaming
payload to prove that the original hashes still match. Existing frozen replay
and scoring paths, prompts, schema bytes and windows are preserved.
